# 遗物美术生成 Prompt 模板

> 用参考图 `art_src/遗物/` 下的三张手绘（`北山岩.png`、`超硬法棍.png`、`龙鳞碎片.png`）作为**画风锚点**，
> 批量生成其余遗物的立绘。每张图单独一次请求，一次只画一件遗物。

## 一、技术参数（固定，不要改）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 接口 | `POST {BASE}/v1/images/edits` | multipart 表单 |
| 参考图 | `image` 字段**重复 3 次** | 依次为北山岩/超硬法棍/龙鳞碎片；数组写法 `image[]` 会 422 |
| `model` | `openai/gpt-image-2.5-flare` | 也可用 `-sunburst`，实测两者行为一致 |
| `size` | `1024x1024` | 与手绘参考一致 |
| `quality` | `high` | **不传默认是 `low`**，必须显式传 |
| `background` | `transparent` | 实测有效：输出 PNG 自带 alpha，**无需再抠图** |
| `output_format` | `png` | 传 `webp` 会被静默忽略 |
| 取图 | `data[0].b64_json` | `url` 字段恒为 `null`，别指望下载链接 |

不要传 `response_format`（被 400 拒绝）、`input_fidelity`（该模型不支持）。

## 二、Prompt 模板（正文）

把 `{遗物名称}` 和 `{外貌描述}` 替换成 `battle_gameplay/RELICS.md` 里对应条目的
`* 外貌：` 那一行，其余原样照发。

```
【任务】
参照所给的三张参考图，绘制一件游戏道具立绘。参考图只用于确定画风，其中出现的石头、面包、黑色鳞片等具体物件不要出现在成图里。使用较粗笔触，绘制完成度较低且风格匹配参考图的画面为第一优先级，其次尽量向遗物文本描述靠拢。

【画面内容】
只画一件物品：{遗物名称}。
{外貌描述}

【画风】
尽量和参考图片风格贴近：柔和厚涂质感的数码绘画，完成度适中，细节简略。

【构图】
单一物体，居中悬浮，不接触画布边缘，不被裁切。物体约占画布高度的 55%–70%。视角与参考图一致：略微俯视的四分之三侧视。物体剪影外侧有一圈干净、连续、粗细均匀的白色描边，紧贴轮廓，不要锯齿与断口。

【背景与禁忌】
背景完全透明。画面中除该物品外没有任何其他东西：没有场景、地面、投影、光斑、色块、边框、装饰花纹。不出现文字、数字、签名、水印、logo。不出现人物、手、或说明性的箭头与标注。不要多个物体，也不要成套陈列。
```

## 四、几点提醒（2026-09-11 实测结论）

- **完成度的第一驱动是「外貌描述里有没有高频名词」，不是风格措辞。** 描述里出现水滴、绳结、裂纹、
  刻度、字迹、划痕这类高频名词时，模型会逐一刻画，出图直接跳到 3D 渲染级的完成度；把它们删掉、只留
  「是什么 + 大致轮廓 + 主色/主材质」（见 `battle_gameplay/RELICS.md` 的改写版），留白交给模型自由
  发挥，它才会向参考图的简略质感收敛。**实测（号角）：物体内一阶梯度密度 52.6 → 31.0（−41%）**；
  光滑小圆盾那类简单形体本来就不高（23 上下），读不出差别。**描述宁可模糊，也不要"写全"。**
- **强提示句「使用较粗笔触，……其次尽量向遗物文本描述靠拢。」**（模板里已放在【任务】段末）与
  【画风】段首两种位置都试过：视觉上都在往简略走，但叠加在留白描述之上后，两处差别落在跑图随机性里
  （号角 30.0 vs 31.2，光滑小圆盾 28.9 vs 22.8），**没有可复现的差别**。它的价值是给风格一个显式
  优先级，成本为零，保留。
- **风格措辞本身可以微调，但别指望它救场**：把「完成度适中，细节简略」换成更狠的"概念色稿"版
  （`--style v4`）能再降一档，但也容易把形体画糊；描述留白之后原措辞已经够用。
- **参考图只锚画风**：模板里明确让模型忽略参考图的具体物件——否则它容易把石头/面包/鳞片的元素带进新图。
- **白色描边是这套画风最显眼的特征，也最容易画毛**：与物体复杂度强相关（简单几何体好，绳结/碎砖这类
  碎细节容易画断、画成毛刷状）。描述留白之后描边明显变干净。
- **透明区微尘是必清项**：输出 PNG 的透明区里有大量孤立小团，实测**全部是 alpha=1 的像素**（合成到白底
  后肉眼不可见，但纹理过滤/缩放后会出彩色毛边）。脚本落盘前会自动做一次保守清理（只删「面积 < 300px
  且最大 alpha < 16」的连通域，主体永不删），约 40s 的图能清掉 200–800 处；`--no-clean` 可关，
  `--clean-only` 可补清已有产物。整体不需要抠图。

## 五、批跑脚本

两个引擎共用本模板；产物按用途分在 `art_src/遗物/` 下的子目录。

**gpt-image-2.5（`tmp/relic_batch.py`，中继 `https://api-o.jeremyguo.space/v1`）**

```bash
cd tmp
RELAY_API_KEY=... python relic_batch.py --dry-run --only 山泉壶        # 只看 prompt
RELAY_API_KEY=... python relic_batch.py --only 号角 天青石              # 试跑几件
RELAY_API_KEY=... python relic_batch.py                                # 全量（已存在的跳过）
RELAY_API_KEY=... python relic_batch.py --clean-only                   # 补清已产物的微尘
```

- 单张约 35–45s；网络类失败退避重试 3 次，4xx 直接放弃。
- 开关：`--style v2|v3|v4|v5`（【画风】措辞变体，v2 = 定稿）、`--priority none|task|style|both`
  （强提示句位置，默认 `task`）、`--out-dir` / `--suffix`（A/B 对比用）。
- 已有手绘锚点（`art_src/遗物/<遗物名>.png`）的遗物自动跳过。

**seedream（`tmp/relic_seedream.py`，火山方舟 `doubao-seedream-5-0-pro-260628`）**

```bash
cd tmp
ARK_API_KEY=... python relic_seedream.py --dry-run --only 号角
ARK_API_KEY=... python relic_seedream.py --only 号角 --bg chroma --size 1K
```

- 走 urllib 直连 HTTP API，**不需要装 `volcenginesdkarkruntime`**。
- **方舟不吃 `background: transparent`**（实测返回白底 RGB），所以固定 `--bg chroma`：要纯洋红底
  → 内置 `cut_chroma` 抠图（不裁画布、边缘去底色，洋红残留实测 0%）；`--bg white` 只用于对比。
- 单张 20–55s。相对 gpt-image：材质更"顺滑写实"一档、白描边更细更松，且必须自己抠图。
- 参考图 / 模板 / 微尘清理与 gpt 侧共用同一套代码（直接 import `relic_batch`）。
