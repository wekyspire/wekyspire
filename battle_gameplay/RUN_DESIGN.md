# 全局游玩流程与养成体系设计（2026-08-02 定稿，2026-09 修订）

> 范围：单次爬塔（run）的核心玩法循环 + 养成经济。战斗内机制见 SKILL_DESIGN_PRINCIPLES.md，
> 舞台/前端见 STAGE_DESIGN.md。本文档是 run 层 core 基建的依据。
>
> **2026-09 修订**：训练房前移至 4N-2 层、首进阶提前到第 2 层；体修改为隐藏等级（跳过进阶 +1）；
> 战后奖励改**卡包制**（体修/灵脉/通用三分）；灵脉首次点亮开**种子包**（九选三）。

## 1. 核心循环

线性爬塔，**无岔路**（区别于杀戮尖塔）：战斗 — 发育交替循环。

```
战斗 → 战后奖励（固定：金币 + **卡包3选1**）→ 奖励房（四选一，按楼层+种子决定）
     → 战前准备（地图界面：预告下战敌人、装配遗物、安排瑞米、使用主动遗物）
     → 下一层战斗 → …
```

四种奖励房：**老虎机 / 训练场 / 营地 / 事件**。战前准备是每场战斗前的固定阶段（见 §4.5）。

**战后奖励 = 卡包制**（2026-09）：先选卡包，再包内技能 3 选 1。
- 可开卡包：**体修包恒开**（门禁看隐藏体修等级），灵脉包需该灵脉等级 ≥1（木/空内容待实装，暂不出现）。
- 通用灰卡（汲取/魏启罐/激发/杂技等 15 张）**不可直接选择**：按概率 + 保底混入任意卡包的三选一（见 §6.2）。

### 1.1 塔结构与胜负
- **44 层 = 4 章 × (10 普通层 + 1 Boss 层)**，Boss 层为 11 / 22 / 33 / 44（故事模式等情况下可变更）。
- **遭遇编成规模**（2026-09）：第 1 层单敌（教学）；**第 2 场起恒 ≥2 敌**，第 1 章全为双敌，
  第 2-3 章起偶发三敌、第 4 章三敌占比更高（早期难度爬升对齐）。
- **胜利**：杀穿全塔并存活。**失败**：玩家死亡 → run 结束。
- **Boss 奖励**：击杀 Boss 后可删一张卡（局外删卡主途径之一，见 §2.1）。

## 2. 资源基调

- **生命值**：跨战斗持久，不自动回复。
- **魏启（mana）**：**战斗内资源**（寿命 = 战斗内，数值与恢复规则见 battle.md §6）——入战置为上限一半（下取整），每回合开始 +1；
  上限初始 3、**每次进阶 +1**（含每个灵脉的首次进阶；总进阶封顶 6 → 上限 9）。营地/进阶/卡牌效果是战斗内的补充手段。
- 无药水系统。
- **设计基调**：回复手段刻意稀缺，生命与升级时机都是需要全局规划的资源。

### 2.1 卡组规模
- 删卡途径：**Boss 奖励**（每 Boss 一张）+ **部分事件**。除此之外无局外删卡。
- **不鼓励原生小卡组玩法**；作为补偿，提供足够多的通用战斗内过牌、弃牌、焚牌手段。

## 3. 养成要素总览

| 要素 | 载体 | 说明 |
|---|---|---|
| 技能 | 卡组 | 获取（卡包3选1/购买）+ 升阶（训练场/营地/事件）；**灵脉首次点亮**额外获得种子包（九选三，§5.3） |
| 瑞米 | run 级队友 | 升级果喂养变强，解锁更多可选支援功能（列表待补）。**HP 归零 = 被打跑**，之后不再出现在战斗中，直至营地找回 |
| 遗物 | run 级物品 | 罕见且强大（强于杀戮尖塔遗物、数量更稀少），特殊机制走白名单订阅。**有装备上限（初始 2）**，一局获得数（约5~6）大幅超过上限，需在战前准备阶段装卸；部分遗物可在战前准备阶段**主动使用**（见 §4.5） |
| 能力 | 精英/大师能力 | 进阶达标后于下一个事件房选择获得 |

## 4. 奖励房细则

### 4.1 训练场（进阶主途径，固定出现）
- **出现规律：总在 4N-2 层**（2、6、10、14…42；10 层被战前营地顶替、22 层为 Boss）。
- 免费：选并升级一张卡。**若无可升级卡牌，改为可选的抓牌（可跳过）**。
- 消费：花钱 → 3选1 一张 D 级卡 **并** 升级一张卡，最多重复 3 次。
- 每次训练累计 `trainingCount`；**离开训练房时若训练次数达标 → 直接进入进阶事件**（不再延后到事件房）。
- **进阶门槛（2026-09）**：首次进阶仅需 **1 次训练**（第 2 层训练房即可），此后每 **2 次训练** +1 级
  （累计 1/3/5/7/9 → 约第 2/14/26/34/42 层）；总进阶次数封顶 **6**（含「跳过」，见 §5.3）。

### 4.2 老虎机
花费金币抽奖，奖励池：
- 无奖励
- 更多金币
- 高于玩家当前等阶的随机卡（小概率；卡池 = 已解锁卡包并集，不含通用灰卡）
- 瑞米升级果
- 遗物
- **训练次数**（+1 等效训练；效率低于训练场——进阶节奏仍以训练房为主）

### 4.3 营地（三选一，有保底）
- 找回瑞米（若瑞米已被打跑）；
- 恢复瑞米全部状态 + 玩家 35% 最大生命（`CAMP_PLACEHOLDER.restHealRatio`）+ 全部魏启；
- 升级一张卡。
- **保底**：作为常规唯一回复手段，每个 Boss 战前必然出现一次（调度细则待 §9 细化）。

### 4.4 事件
- 脚本化抉择事件（内容留坑）；**部分事件可删卡**（局外删卡途径之二）。
- **S 级卡的获取途径**（S 为中后期内容，具体设计后议）。

### 4.5 战前准备（地图界面）
每场战斗前的固定阶段，承载**地图界面**（高塔外观：右侧为望不到顶底的塔楼、繁星夜空背景、水彩风格，**three.js 渲染**——它属于"舞台"而非剧情幕间）：
- **敌人预告**：下一场战斗的敌人编成在此揭示（遭遇在到达本阶段时按 seed+floor 确定性生成，非进战才roll）。
- **遗物装配**：`equippedRelics`（受 `relicSlots` 上限约束，初始 2）与背包 `relics` 之间装卸；仅装备中的遗物在战斗中挂载钩子。
- **瑞米安排**：切换 `activeSupport`、确认出战状态。
- **主动遗物**：部分遗物带战前主动效果（契约留 `prepUse` 钩子 + 使用次数/冷却字段位），仅在此阶段可用。

## 5. 进阶与等级体系

### 5.1 玩家等级 = 灵脉等级 + 隐藏体修等级
- 玩家有 **3 条互相独立的灵脉等级**：火 / 木 / 空（木、空内容待实装，当前仅火灵脉开放）。维度之间等级互不相干。
- **体修不占灵脉维度**：它有一条**隐藏等级** `player.bodyLevel`，只在进阶事件「跳过」时 +1（§5.3）。
  体修卡包与体修卡的等阶门禁看它；面板不展示——这是故事模式的暗线（体修大成是唯一能稳定打过真结局 Boss 的 build）。
- **附属体系无独立等级**，其等级 = 三条主灵脉等级的**加和**（均衡发展型玩家也能拿到高阶附系卡，"均衡发展"本身就是一种打法）。
- **数值锚点：整场游戏总进阶次数 ≤ 6**（含「跳过」；`ASCENSION_PLACEHOLDER.maxAscensions`）。
  各等阶门槛按**体系自身等级**标定：0 级 → 只出 D/C，1 级 → 解锁 B，2 级 → 解锁 A（专精昂贵是设计意图）。

### 5.2 等阶门禁（按体系独立）
- **灵脉体系**：`leino[维度]` 达标 → 该体系卡包与卡牌升到对应等阶（例：火灵脉等级达标 → 火系卡可升 B/A）。
- **体修体系**：隐藏体修等级 `bodyLevel` 达标 → 体修卡包/卡牌升阶。
- **通用灰卡**无独立等级，跟随所开卡包的门禁展开（§6.2）。
- 附系卡牌按"三主灵脉等级加和"判定。
- **门禁内等阶加权（2026-09 定）**：战后开包与训练抓牌统一概率——相对当前上限，
  本阶 20% / 低一阶 55% / 低两阶 25%，更低阶不掉落；最低档（D）吸收无归属余量
  （上限 C 时 D=80%，即开局体修 C 卡恰为 20%）。实现见 `rewards.js` 的 `TIER_WEIGHTS`。

### 5.3 进阶事件（= 等级提升事件）
- **触发**：离开训练房时训练次数达标 → 直接进入进阶事件（无延后、无随机性；老虎机的"训练次数"奖励为辅）。
- **内容（二择）**：
  1. **选择一条灵脉升级**：该灵脉等级 +1；
  2. **跳过**：不选灵脉，隐藏体修等级 `bodyLevel` +1（体修成长通道，故事模式暗线）。
  两种情况都：恢复全部状态 + 魏启上限 +1 + 消耗一次进阶机会；若达标则**在进阶事件内直接选择精英 / 大师能力**（不再经事件房授予）。
- **种子包（2026-09）**：灵脉**首次 0→1** 时额外开一次「**九选三**」——从该灵脉的 D/C 基石卡中
  抽 9 张互不重复的候选，任选 3 张直接加入牌组，可**刷新一次**（重抽并优先避开已出现的卡）。
  种子池排除「需要前置储备才生效」的组合件（排除表见 `ascension.js` 的 `SEED_EXCLUDED`，
  内容侧也可用 `seedEligible: false` 标注）；**进阶链只开链头**（链中最低级，高阶由局外晋升获得，
  同链 D/C 不并列）；**必出卡**（内容侧 `seedGuaranteed: true`，如火的点火——体系骨架入口）
  每次开包/刷新都占位。**跳过进阶不触发种子包**（体修是初始体系，开局已有小 build）。
- 等阶体系见 SKILL_DESIGN_PRINCIPLES「养成与等阶」：D→C→B→A 阶梯 + S/Z 阶梯外。

## 6. Core 层架构（run 层）

**原则：run 层是普通确定性状态机，不套结算指令树**——指令树是战斗内抽象；幕间交互就是纯函数 + 状态迁移，headless 可测。

### 6.1 RunState（重构现有 `state/runState.js`）
```
{
  seed, rng,            // run 级种子 + 独立 rng 流（奖励生成确定性）
  floor, gameStage,
  player: { …现有字段…, leino: { fire, wood, air }, bodyLevel,  // 三灵脉等级 + 隐藏体修等级（§5.1）
            trainingCount, ascensionCount, relics: [], equippedRelics: [], relicSlots: 2 },
  remi: { level, fruits, drivenOff, activeSupport, unlockedSupports },
}
```
- 战斗种子派生：`battleSeed = derive(runSeed, floor)`，整局可复现。
- 过时字段（`shopItems`/`rewards` 旧义）清除。

### 6.2 模块划分（`src/core/run/`）
- `runFlow.js`：`createRun({ seed, profile })`、楼层推进、奖励房派发。
- `rewards.js`：战后奖励（金币 + **卡包3选1**）与卡池生成——**三分卡包**（体修 / 灵脉 / 通用），
  门禁按体系自身等级（体修看 `bodyLevel`）；通用卡以 `COMMON_INJECT`（30% + 每 4 次开包保底）
  替换任意卡包三选一中的一张，门禁达 B 以上时剔除 D 级（保证「出现即有价值」）；
  训练房抓牌走「已解锁卡包并集」并同样注入通用卡。
- `rooms/slotMachine.js`、`rooms/training.js`、`rooms/camp.js`、`rooms/event.js`：各房操作函数（纯函数，走 run rng）。
- `promotion.js`：局外升级（换 deck 内 runtime 的 defId、重置充能；卡定义加 `promotesTo: defId | [defIds]` 支持分叉，取代旧 precessor 逆链）。
- `ascension.js`：进阶事件结算（灵脉升级 / **跳过 = 隐藏体修等级 +1** + 全恢复 + 魏启上限提升 + 能力授予
  + 灵脉首次点亮的**种子包**九选三）。

### 6.3 契约扩展
- **遗物**：`core/relics/registry.js`，契约镜像 ability（`onBattleStart`/`subscriptions`/`applyRunModifiers`）+ **`prepUse?(runState)` 战前主动钩子**（带次数/冷却字段位，仅战前准备阶段可触发）。独立注册表（获取途径/稀有度/UI 不同，钩子机制共享）。战斗装配时仅挂载 `equippedRelics` 中的遗物与 abilities。
- **技能 spawn 元数据**：定义补 `pack`（`'body'|'fire'|'wood'|'air'|'common'`）、`canSpawnAsReward`、
  `seedEligible`（种子池可选性）。旧设想的「灵脉相性权重」由卡包制取代，不再需要。
- **瑞米**：ally 定义加 `createUnit(level)` 等级缩放 + `supports: [{ id, name, act }]` 可选支援位；run 状态记录 `activeSupport`，战前可切换。
- **等阶门禁**：卡定义升级合法性判定 = 该卡所属体系等级 ≥ 目标等阶门槛
  （灵脉取 `leino[维度]`，体修取 `bodyLevel`，附系取三主灵脉等级加和），见 §5.2。

### 6.4 故事模式接缝（只留缝，不建管道）
- `createRun({ seed, profile })`：profile 携带跨局持久内容（如 `remiBaseLevel`、已解锁支援）。单次游玩传空 profile，行为不变。
- 瑞米状态 = **基线（profile）+ 局内增量**；run 结束可导出结算摘要供未来合并回 profile。
- 纪律：run 状态只存 id 与数字（沿用效果系统可序列化约束），不挂闭包——未来存档白捡。

### 6.5 SDK
- `RunDriver`（类比 BattleDriver）：一行跑整局，供 agent 批量 headless 验证经济平衡与奖励分布。
