# CARD_ART.md — 卡面图管线（场景时代）

> 卡面图的设计口径与生产管线。卡面图 = **骑士出演的动作场景**（图标化的厚涂速写），
> 不是符号徽标，也不是插画——「展现动作的基础上进行图标化」：弱化细节、大块纯色概括形体、
> 表现力优先（用户 2026-09-22 二轮定稿，取代首轮符号口径）。

## 一、设计口径（用户 2026-09-22 定）

- **演员 = 骑士**：玩家卡的卡面统一画骑士做那件事（挥拳、托焰、坐云……），一眼认出是什么卡。
  Z 状态/敌方衍生卡没有骑士——画那个东西本身（烟问号、绷带灼伤、尘云、黏液怪……）。
  **例外家族**：枪系全走无人物件微距（弹道/弹壳/枪口焰——画人必拉出步枪现代兵，破设定）；
  刀系（blade）**刀刃本身是主体**，骑士可淡化到画缘或只留持刃的手。
- **风格**：粗糙厚涂速写（rough gouache）、极宽大笔触、极低完成度、多边形色块、
  美漫式强烈光影分割、冷光自左上、无勾线、**纯黑背景**、主体撑满画幅、紧致特写裁切。
  锚图 = `art_src/骑士概念.png`（构图/角色）+ `art_src/角色/骑士背面-普通png.png`（笔触粒度）。
- **氛围 > 精细表达（2026-09-22 用户定，锚 = `art_src/氛围参考-围巾骑士.png`）**：
  表达靠剪影与动作态势，形态溶入大色面与光影团块，细节交给观看者脑补。
  评测时不以「画得细」为好，以「卡面尺寸下一眼读对氛围」为好。
- **角色设定（不可破）**：闷钢灰全身板甲（保留金属感、略压暗）、同色圆盔、**细淡横面甲缝、
  眼不发光**、五指、亮红围巾（唯一色彩强调）。
- **武装设定（2026-09-22 用户定）**：骑士**无盾**——格挡只靠臂甲（crossed vambraces）；
  佩**大剑**（直刃双手巨剑），不是刀。法术效应（灵能屏障/树皮甲）不受「盾」禁词约束，
  但骑士本人永不持盾。
- **构图原型配额（2026-09-25 用户定，最高优先级设计律）**：骑士当主体曾占 65/204 键 →
  「都是骑士在干啥」辨识度崩盘。全库四原型轮转，写 prompt **先选原型再填内容**：
  ① **部位微距**（拳/掌/臂甲/靴/盔填满画幅）② **剪影环境**（骑士缩小为小黑影置于大现象中：
  血海/护盾泡/火墙/月夜——现象才是主体）③ **动态抽象**（速度线/残影/刀光轨迹为主体，无整体人）
  ④ **物件主体**（那东西本身：罐/刃/弹道/火）。骑士全身/半身主体仅保留 8 键「确实帅」名额
  （airFloat/flameHeal/fireWhirl/lastStand/pluckStar/allIn/atEase/noonNap），新增须用户点头。
  等阶分级轴随之扩容：除「点名新增元素」外，可用**饱和度/亮度/密度连续轴**
  （血拳=血色鲜艳度、灵能护盾=护盾亮度、狂拳=红黑速度线密度——连续轴对 img2img 级联尤其友好）。
- **体修部位特写纪律（2026-09-22 用户定）**：体修系列不能只靠骑士姿态区分
  （半身像必然趋同）——**部位微距是主要区分轴**：拳/掌/肘/臂甲/靴/面甲各成一景，
  只有动作本身是定义的卡（冲拳、连打）才用全身/半身动态。近义键先分部位、再分手势。
  （2026-09-25 起并入上方四原型体系，为其①之细分。）
- **灵能/魏启 = 淡蓝主题（2026-09-25 用户定）**：灵能系卡（护盾泡等能量体）与魏启
  相关素材一律 pale light blue 主题色（魏启水晶/蓝罐延续既有蓝系；生成 prompt 显式
  写色锚——灵能护盾首版生成出无彩灰就是没写色锚的教训）。
- **体修虚无 flavor（2026-09-22 用户定）**：体修越高深，内核越「虚无、简单、幻灭、空洞」——
  高阶变体倾向低饱和、纯黑白强对比、笔触模糊虚幻（红围巾作唯一残色）。按卡名意境选择性落实，
  不一刀切（实现见生成器 `ESCALATION_VOID` 表）。
- **无 alpha**：场景全幅黑底，直接 cover 进 ART_RECT，不做抠图。
- 粒度沿用：**每系列/家族一键**（`series` 键；无系列灰卡经 `def.image` 逐卡接线）。

## 二、解析链（`src/stage/art/cardArtCache.js`）

```
def.image 的等阶变体 `${image}-${tier}`  →  def.image
card.series 的等阶变体 `${series}-${tier}` →  card.series
`${type}-${等阶序号}`（D=0..S=4，兜底，现无素材）
```

**等阶梯度变体（2026-09-22 用户定）**：不同系列必须异图；同系列升级较大时也要异图——
**同一动作、越来越强**。变体键 = `<基础键>-<等阶序号>`；系列内**最低在册等阶沿用基础图**，
其余每个等阶一张变体（如 blade 系 C–S：blade-2/3/4，blade 基础图服务 C 阶）。
素材缺位自动回落基础键，core 内容零改动。

**同链构图连贯（2026-09-22 用户定）**：同一升级链路的卡面构图必须相似——玩家一眼认出
同链，同时差异清晰可见（角色状态/背景/笔触/刀刃形态色泽逐级变化）。
「构图不变」不等于「一切不变」，进阶幅度要读得出「一重更比一重强」。

素材位 = `src/assets/cards/<key>.webp`（704×352，2:1 全幅场景；卡面 ART_RECT 176×88 cover 贴合，
上下渐隐进卡底色 + 主题色描边）。等阶普查脚本 `tmp/dump-series-tiers.mjs` → `tmp/series_tiers.json`
（2026-09-22 普查：**204 活键 / 119 多等阶键 / 211 变体位**，链感知：同链卡经 `def.image` 归并）。

## 三、生产管线（本地 ComfyUI，免费可重跑）

```bash
node tools/genCardScenes.mjs [--only=key1,key2] [--count=N]   # ① 逐键抽卡 → art_src/cards_scenes/<key>/cand_<i>_<seed>.png
node tools/genCardScenes.mjs --chain=k0,k1,... [--anchor=图]  # ①b 跨键链级联：k0 参考既有图，其后逐级 img2img
node tools/genCardScenes.mjs --varchain [--only=key1,key2]    # ①c 键内等阶变体级联（读 tmp/series_tiers.json）
python tmp/sheet_keys.py out.png key1,key2,... [cols] [W] [H] # ② 联排拼版（审视最小单元）
python tmp/deploy_scenes.py                                   # ③ 按 tmp/scene_picks.md 胜者 → 中裁 704×352 → webp
```

- **参数一律等号连接**（`--only=x,y`）——空格分隔会被静默忽略，变成全量批跑！
- 生成器：`tools/genCardScenes.mjs`。KNIGHT/STYLE/NEGATIVE 三常量 = 定稿风格口径；
  SCENES 表 = 每键一句手写 prompt（**不准交给模型写**）。每条 prompt **自包含**——
  图像模型没有跨 prompt 上下文，风格句、角色句、构图轴必须每条带全。
- **prompt 编写纪律（2026-09-22 用户严令）**：英文键名与卡面中文名/效果可能严重偏离——
  写 prompt 前必须读该键全部卡的中文名 + describe + 所属体系设计文档
  （`battle_gameplay/skills/*.md`）理解家族内涵，画面语义以中文卡面为准。
- **防同图纪律**：同一演员 + 紧特写口径下，「骑士胸前一点小火光」式 prompt 必然收敛成
  同一张图。写 prompt 必须**先定构图轴**（机位/姿态/景别），再填内容物；
  近义键（掌火系、咏唱系、格挡系、姿态系）两两构图轴不得相同。
- **语义判重（2026-09-22 用户定，取代 ahash 数值门禁）**：构图相似不是 metric 能衡量的——
  评判标准 = **玩家面对两张卡时，能否自然将它们关联（同链/同族），其中差异又清晰可见**。
  同链对：关联 ✓ + 差异 ✓ 才算过；跨族对：被误认作同一张卡即败。靠人眼联排审视，不设阈值。
- **迭代工作法（2026-09-22 用户定）**：**只能迭代收敛，不能一轮 prompt 批量结算**——
  生成一批 → 联排审视 → 对不足者定点重跑（`--only` / `--chain` / `--varchain`，新候选追加不覆盖）→
  复审。首轮 204 键中约 60 键经过 2–4 轮返工才收敛。
- **两级级联（2026-09-22 定）**：
  - **跨键链 `--chain`**（斩链 rockCleave→…→godCleave）：链首以既有部署图为参考，其后每级
    以前一级**新图** img2img（`CHAIN_DENOISE=0.85`）——构图锁死、逐级升维。链内键不走独立
    txt2img（构图各自漂移、玩家认不出同链）。
  - **键内变体 `--varchain`**：每键以**已部署的 webp** 为锚，逐级 img2img
    （`VAR_DENOISE=0.8`），后缀按等阶递强——同一动作、越来越强。取代旧 txt2img `--variants`
    （独立生成必然构图漂移，正是用户否决的「同链路认不出」）。
- **等阶后缀三表**（生成器内，按键查 `ESCALATION_VOID[key][tier] → ESCALATION_CUSTOM → ESCALATION`）：
  通用 `ESCALATION`（1=C 微强 … 4=S 终极爆发）；**按键定制 `ESCALATION_CUSTOM`**——铁律：
  后缀必须**点名新增可视元素**（裂纹/尘土/光膜/残影/血珠），不许只写「更强更亮」
  （通用措辞在微距场景上被 0.8 保真压过、进阶不可读——首轮评审 38/60 键因此返工）；
  体修高阶走 `ESCALATION_VOID`（褪彩→黑白→虚空，红围巾唯一残色，优先级最高）。
- ComfyUI `127.0.0.1:8188`，qwen_image_2.1，25 步 euler，**800×400**（2026-09-22 用户定：
  800 宽够用、省时 3 倍），单张约 30–40s；已存在的跳过（resume），`--count` 控制目标张数；
  多个 node 进程共享同一 FIFO 队列，可并行跑不同键段。

## 四、踩坑记录（场景时代实测）

- **文件零共用 ≠ 视觉不撞车（最大坑）**：71 键无一跨系列共用文件，玩家仍看到「不同系列图
  完全一样」——根因是**构图收敛**。排查 = 卡面实尺联排；修复 = 构图轴先行改写，不是换内容物。
- **模型先验会抢戏**：「太极卸力」必出宽袍人（off-canon 无甲）——要写成「钢灰板甲手套接住
  一道亮力 streak 拨向一旁 + no robes no fabric」；「木桩」先验里没有稻草人（会画出光头人）；
  「花式挥刃」必画光环圆阵（perfectCleave 与 cycloneSlash 撞车）——改「平放钢刃蔷薇花」；
  枪系画人必拉现代步枪兵。遇到先验抢戏，换具体物体名词 + 显式否定词，别在抽象词上加码。
- **模型会漂移，prompt 对了不等于图对了**：kindling 写「臂上血滴着火」首批画成普通拢焰——
  评审按卡面语义挑候选，不是按构图美观挑。
- **img2img 强度刻度（实测）**：denoise 0.6 = 克隆参考图；0.72 ≈ 零变化（褪彩压不过保真，
  试点被拒）；0.8 = 构图锁死 + 后缀显形（变体级联用）；0.85 = 逐级变身真正发生（跨键链用）。
- **超时偶发**：单张 ~5% 超时，resume 重跑补齐即可。
- 符号时代的灰卡 prompt 坍缩教训仍适用：抽象词 → 毛笔符文；写**具体物体名词**。
- 旧符号管线（`tools/genCardArt.mjs` + `tools/cutCardArt.py`）已退役，仅存档备查。
