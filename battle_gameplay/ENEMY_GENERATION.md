# 敌人生成 · 难度制 v2（2026-09-24）

> 权威实现：`src/core/run/floorEnemyGenerator.js`（曲线/模板/选材）+
> `src/core/content/enemies/`（难度元数据跟各文件走：`chapter1.js`~`chapter4.js` 小怪、
> `elites.js` 精英、`bosses.js` Boss）。调平衡只动这些文件与生成器常量。
> 第一章个体设计卡见 `battle_gameplay/ENEMIES_1.md`。

## 1. 核心概念

- **楼层难度 D(floor)**：一层的战斗总预算。开局几层陡升（教学单挑 → 双敌），
  此后每 2 层 +1 稳定爬升；Boss 层走独立难度表。
- **敌人难度元数据** `{ base, floorMin, floorMax }`（v2 起**取消单敌人缩放**）：
  - `base`：固定难度（该敌的战力档位，仅作生成选材与展示/调试——数值恒用
    `createUnit()` 的授权面板，不再按难度缩放）；
  - 楼层 `∈ [floorMin, floorMax]`：超出则**该敌人不再生成**——机制老旧
    （教学杂鱼）或数值漂移超出设计包络（44 层不该出现超级史莱姆）；
  - `unique: true`（可选）：**每场至多一只**（如怨灵——虚弱不衰减，成对出现
    会把永久减攻叠到无法翻盘；选敌时已被占用的 unique 不再进池）；
  - `elite: true`：精英标志——挡在普通通配池外，只经精英房模板出场。
- **战斗模板（主题编成）**：固定结构 + 楼层区间 + **编成难度**（各槽代表难度之和：
  钉死位取该敌 base，通配位取当层池 base 的最小值——通配位是变量，模板难度只作锚）。
  模板按「编成难度落在 [D−2, D+2] 漂移窗内」筛选后加权随机取用（距 D 越近权重越高）。
- **取材池按 id 排序**：注册顺序随内容文件组织方式漂移，排序后遭遇分布与
  文件布局彻底解耦（同 seed 同层恒定不受拆分/挪动影响）。

### 4.1 精英怪

- **定义**：`difficulty.elite: true`。机制更强、基准数值更高，战力≈两个普通敌人；
  永不进入普通通配池（普通层见不到精英）。
- **数值口径**：v2 起精英也是固定数值（`createUnit()` 授权面板，不再缩放）——
  「基准数值按自身 base 授权」的旧话只保留历史意义：base 现在是该精英的
  战力档位标签（雪狼 base 5 ≈ 两个 d2 白板），不再驱动任何缩放公式。
- **排期（确定性）**：每章第 6、9 层（6/9、17/20、28/31、39/42）为精英层，
  当层只从精英房模板取材；该章尚无精英内容时自动回落普通编成
  （当前章 2、章 4 即如此——加精英零生成器改动）。
- **奖励**：精英/Boss 战后走 `elite` 奖励通道（B 65 / A 35，**A 直出只挂这里**；
  分布与口径见 `REWARD.md`）。

## 5. 生成算法（确定性，同 seed 同楼层恒定）

1. Boss 层 → 从当层候选池抽一只 Boss（难度仅作展示/调试，数值固定）；
2. 取当层可用池，计算各模板的**编成难度**（各槽代表难度之和：钉死位取该敌
   base，通配位取当层池 base 的最小值）；
3. 模板筛选：楼层命中 + 精英标志匹配 + 编成难度落在 **[D−2, D+2] 漂移窗内**；
   窗内无货时取编成难度最近者贴线收场（不报错）；
4. **加权随机**：编成难度距 D 越近权重越高（差 0 → 4，差 1 → 2，差 2 → 1），
   随机取一；
5. **槽位取材**：钉死位直接用；通配位从池里按 base 就近取材（优先贴槽位代表
   难度，并列随机）；unique 敌人已被前面槽位占用则不再进池；
6. **编成后处理**：同种错拍（§4.0）＋ 石茧群 / 音叉群的延迟苏醒变体参数。

## 6. 已知取舍 / 后续方向

- **v2 的漂移语义**：模板按「编成难度」（各槽代表难度之和）进漂移窗，槽位再按
  base 就近取材——两步走会导致实际编成偶尔漂出窗口 ±1（通配位取到比代表难度
  高的怪），落在「接近层总和」的容差语义内。要更准就得先取材再过滤，复杂度不划算。
